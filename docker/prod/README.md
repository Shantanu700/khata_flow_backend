# Production on Render's free plan

The API runs as one Docker web service on Render (free, Singapore). One uvicorn process serves both the REST API and the live-transcript WebSocket. Render provides HTTPS and an `https://<service>.onrender.com` address.

The database is Supabase (free) and photos and voice audio are in Cloudflare R2 (free). The service's own disk is wiped on every deploy, restart and spin-down, so nothing is kept on it.

## What the free plan means

- **Sleeps after 15 minutes without requests.** The next request wakes it, which takes about a minute. A shopkeeper opening the app after a quiet spell waits that long once.
- **0.1 CPU and 512 MB memory.** Spoken commands are slower than on your machine (ffmpeg and Django share a tenth of a CPU).
- **750 free hours a month** per workspace: enough for this one service running all month.
- Render says free instances are not meant for production. Moving to a paid plan later is a dropdown change; nothing else changes.

## 1. Accounts (once)

- **Supabase**: a new project in **Southeast Asia (Singapore)**, next to the Render service (each request makes several database calls, so the distance adds up). Copy the **Session pooler** connection string (Project > Connect) and add `?sslmode=require` to the end.
- **Cloudflare R2**: the bucket and token from `.env.example` in the repo root.
- **Render**: sign up with GitHub and allow it to read `Shantanu700/khata_flow_backend`.

## 2. Create the service

1. Render dashboard > **New** > **Blueprint** > pick this repo. Render reads `render.yaml` from the repo root.
2. Render asks for each value marked `sync: false`. Fill in:

   | Setting | Value |
   |---|---|
   | `ALLOWED_HOSTS` | `khataflow-api.onrender.com` (if Render gives the service a different address, use that) |
   | `CSRF_TRUSTED_ORIGINS` | `https://khataflow-api.onrender.com` |
   | `VOICE_STREAM_URL` | `wss://khataflow-api.onrender.com/api/v1/voice/stream/` |
   | `CORS_ALLOWED_ORIGINS` | the web app's address once it is deployed, e.g. `https://khataflow.<you>.workers.dev` |
   | `DATABASE_URL` | the Supabase session pooler string, ending in `?sslmode=require`. If the password has symbols, URL-encode it first: `python3 -c "from urllib.parse import quote; print(quote(input(), safe=''))"` |
   | `R2_*` | the four R2 values |
   | `GNANI_API_KEY`, `LLM_API_KEY` | the voice and LLM keys |

   `SECRET_KEY` is generated by Render. The other settings are already filled in by `render.yaml`.
3. **Apply**. The first build takes a few minutes. When the log shows `Uvicorn running`, open `https://<service>.onrender.com/api/v1/i18n/`.

If the address Render gave differs from what you typed, fix the three address settings under the service's **Environment** tab and save (that redeploys).

Every push to `main` deploys again.

## Migrations

Migrations are generated, not committed. Each start (deploy, restart or wake-up) runs `makemigrations` and then `migrate`.

This works while the models stay as they were at the first deploy. **After the first deploy, a model change does not reach the database by itself**: the fresh container generates a new `0001_initial`, which the database already counts as applied. Before deploying a model change, apply it to Supabase by hand, or start committing migrations.

## Admin account

Render's free plan has no shell. Create a superuser from your machine against the Supabase database:

```bash
docker compose -f docker/nonprod/docker-compose.yml run --rm --no-deps -e DATABASE_URL='<the Supabase string>' web python manage.py createsuperuser
```

Shops sign up through the web app.

## Good to know

- **Supabase free pauses a project after a week with no requests.** Resume it from the Supabase dashboard.
- **Logs**: the service's **Logs** tab. Access logs are off on purpose, because the live-transcript ticket travels in the WebSocket URL.
